# assets/ — 영상에 넣을 자산

여기에 파일을 놓고 시나리오에서 **파일명만** 가리키면 됩니다. 경로는 시나리오 파일 기준입니다.
없으면 없는 대로 영상은 나옵니다. 다만 아래 순서대로 효과가 큽니다.

---

## 1순위 — 로고 (가장 효과 대비 쉬움)

```
assets/logo.svg      또는 logo.png  (권장: SVG, 또는 투명 배경 PNG 높이 200px 이상)
```

`scenarios/ir-full-tour.json` 최상단에 한 줄:

```json
"brand": { "logo": "../assets/logo.svg" }
```

카드 8장 전부 좌측 상단에 자동으로 들어갑니다. **어두운 배경 위에 올라가므로 흰색/밝은
단색 버전**이 필요합니다. 컬러 로고만 있으면 흰색 버전을 따로 주십시오.

---

## 2순위 — 제품 실물 사진

투자자는 소프트웨어 화면만으로는 "실물이 있는가"를 확인하지 못합니다. 사진 1~2장이
전체 신뢰도를 올립니다.

```
assets/product-uid.jpg      제품 하단 UID 라벨 클로즈업  ← 가장 중요
assets/product-hero.jpg     제품 단독 또는 진열 상태
assets/kiosk.jpg            실제 키오스크 기기
assets/field.jpg            현장 단속 요원이 앱으로 스캔하는 장면
```

- **해상도 1920×1080 이상**, 가로. 세로 사진은 좌우가 잘립니다.
- 카드 배경으로 깔리고 좌측에 검은 그라데이션이 덮이므로, **피사체를 화면 오른쪽**에 두고
  찍은 사진이 가장 잘 맞습니다.
- 사람 얼굴이 식별되면 **촬영 동의**를 받아 두십시오. IR 자료는 외부로 전달됩니다.

시나리오의 카드에 한 줄:

```json
{ "id": "05-title", "card": {
    "eyebrow": "LEDGERMARK · 필리핀 전자담배 유통 추적",
    "headline": "등록된 순간부터, 끝까지 추적되는 유통",
    "sub": "...",
    "image": "../assets/product-uid.jpg"
} }
```

**UID 라벨 클로즈업을 00번(문제) 또는 05번(타이틀)에 넣는 것을 권합니다.** 영상 전체가
"이 UID 하나를 따라간다"는 구조이므로, 그 UID의 실물을 먼저 보여주면 뒤가 전부 구체화됩니다.

---

## 넣지 말 것

- **스톡 사진.** 심사역은 스톡을 한눈에 알아봅니다. 실물이 없다는 신호로 읽힙니다.
- **합성·렌더링 이미지를 실물처럼.** 렌더링이면 렌더링이라고 캡션에 적으십시오.
- **타사 제품·브랜드가 식별되는 사진.** 상표 문제가 됩니다.
- 이 폴더의 **이미지 파일은 `.gitignore` 처리되어 저장소에 올라가지 않습니다**(이 README만 추적).
  공개 저장소라 출시 전 제품 사진이 그대로 공개되는 것을 막기 위해서입니다. 대신 다른 PC에서
  촬영할 때는 파일을 직접 복사해 오셔야 합니다.

## 확인

```bash
npm run check -- scenarios/ir-full-tour.json --check
```

파일이 없거나 형식이 틀리면 **녹화 전에** 파일명을 찍어 알려 줍니다.
지원 형식: `.svg` `.png` `.jpg` `.jpeg` `.webp`
